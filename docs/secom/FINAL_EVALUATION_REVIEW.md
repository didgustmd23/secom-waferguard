# 최종 평가 전 점검과 동결 제안

작성일: 2026-10-07. 현재 상태: **사용자 동결 승인·후속 평가 완료, 정책 목표 미달**. 최초 점검에서는 Test CSV·후보 joblib을 읽지 않았다. 이후 사용자가 승인한 조건으로 평가했으며 완료 기록은 아래 7절에 추가했다. 최초 점검의 설명과 명령어는 이력으로 보존한다.

## 1. 확인 결과

| 항목 | 확인 내용 | 판단 |

실행 기록의 `test_used=false`나 `is_final_test=false`는 해당 실행의 범위를 나타낸다. 속성이 없는 기록은 미확인이지 자동으로 미사용이라는 뜻이 아니다. 경로 확인은 실제 행·센서 값·모든 과거 수동 실행을 포괄하는 감사가 아니다.

보고서의 과거 Random Train·Time Validation 중복 기록은 기존 탐색 결과의 해석 이력이다. 이번 점검에서 최신 Pipeline의 데이터 누수를 새로 확인한 것은 아니다.

## 2. 동결 승인한 현재 후보

사용자의 “그렇게 해” 승인으로 아래 저장 후보를 **연구·데모용 최종 평가 대상**으로 고정한다. 새 학습이나 설정 변경은 하지 않는다. 여기서 동결은 평가 조건의 기록이며 파일 쓰기 잠금이나 현장 배포 승인을 뜻하지 않는다.

- 학습 범위: 기존 Time Train 1,096행. Validation·Test를 추가하여 재학습하지 않음.
- 대상 묶음: `models/candidates/m3_sensor20/candidate.joblib`와 동일 폴더의 manifest.
- 선택기: S0 RF, 트리 300개·최소 leaf 1·깊이 제한 없음·seed 42.
- 분류기: M3 XGBoost, 트리 300개·깊이 2·`reg_lambda=5`·학습률 0.05·subsample/colsample 0.8·양성 가중치 1·seed 42.
- 입력 센서: 저장 manifest와 [후보 Model Card](model_card.md#4-저장된-입력-계약)의 순서 있는 20개 목록. 평가 입력에서 재선택하지 않음.
- 전처리: 저장된 학습 median. 이 후보에는 scaling 없음. 평가 입력으로 통계를 재계산하지 않음.
- 양성 label: `1`, 정상 label: `-1`.
- threshold: **`0.036539457738399506`**. Test를 보고 변경하지 않음.
- 비교 정책: Recall 80%·양성 판정 비율 상한 40%. 현장 표준이 아닌 프로젝트 시나리오.
- 평가 후보 파일: `data/splits/integrated/time_test.csv`. 이번 점검에서는 내용 미열람.
- 지표: AP·Recall·Precision·F1·ROC-AUC·양성 판정 비율·TP/FP/FN/TN 및 표본 수.
- 전체 선택 센서 결측 행: 모델이 예측을 거부하므로 자동 제외하지 않음. 평가 전 입력 검증에서 중단하고 처리 조건을 별도로 결정. 예측 가능한 행만 남겨 전체 성능으로 보고하지 않음.
- 결과 목표: 목표 미달도 그대로 기록. 현장 배포·실제 검사 장비 성능·2단계 딥러닝 효과를 주장하지 않음.

평가가 이루어져도 기존 후보를 자동으로 현장 배포 모델로 바꾸지 않는다. `is_final_model=false`를 승인 없이 변경하지 않는다.

## 3. 평가 표현과 사용 이력 확인

사용자 승인에 따라 **“기존 데이터의 후속 시간 구간 평가 — 과거 사용 이력상 완전한 미사용 여부 보증 불가”**로 표시한다. 완전히 미사용인 독립 Test라는 표현은 사용하지 않는다.

- 과거 Random Train 또는 다른 탐색에 최종 Time Test의 행이 포함됐으면, 현재 모델의 직접 학습에서 제외했더라도 프로젝트 전체에서 완전히 미사용인 평가로 설명할 수는 없다.
- 과거 포함 여부가 미확인이면 평가 자체를 금지할 필요는 없지만 그 불확실성을 최종 보고서에 명시해야 한다.
- 처음부터 제외했고 모델·센서·문턱 선택에도 사용하지 않았다는 근거가 있으면 그 범위 안에서 미사용 평가로 표현할 수 있다.
- 새로 분할하거나 파일명을 바꿔도 이미 관찰한 데이터의 사용 이력은 초기화되지 않는다.

현재 남아 있는 실행 JSON만으로는 과거의 모든 실행과 행 포함 여부를 확정할 수 없다. 필요하면 후속 단계에서 split의 원본 행 ID만 대조하는 검사를 별도로 준비한다. 그 검사에서 Test의 label·센서 값으로 모델을 조정하지 않는다.

## 4. 사용자 결정 기록

체크박스는 승인 기록용이며 코드나 설정을 자동 변경하지 않는다.

- [x] Test 결과에 맞춰 문턱·센서·모델을 다시 변경하지 않는다.

선택 근거: 현재 실행 JSON과 보고서만으로 모든 과거 탐색에서의 최종 Time Test 행 사용 여부를 확정할 수 없다. 미사용이라고 추정하지 않고 불확실성을 유지한다. 이는 현재 코드의 누수가 확인됐다는 뜻이 아니다.

최종 평가 표현: 기존 데이터의 후속 시간 구간 평가 — 과거 사용 이력상 완전한 미사용 여부 보증 불가.

## 5. 승인 후 진행 순서

1. 사용 이력 상태와 평가 표현을 기록한다. 불확실성을 숨기지 않는다.
2. 저장 후보를 그대로 읽는 최종 평가 실행 코드를 준비한다. 새 fit·센서 선택·threshold 탐색은 하지 않는다.
3. Train과 평가 split의 계약·역할·원본 ID 비중복·시간 경계, 입력 계약을 검사한다. 이 검사는 과거 개발 사용 이력의 초기화를 뜻하지 않는다.
4. 사용자가 명시적으로 실행할 때 한 번 평가하고 실행 기록과 성능·오류·거부 여부를 저장한다.
5. Model Card·보고서·README에 실제 평가 범위와 한계를 반영한다.

이번 단계에서는 사용자 승인에 따른 동결 기록만 반영했다. 모델 묶음·설정은 변경하지 않았으며 최종 평가 코드를 실행하지 않았다. 다음은 승인한 조건으로 저장 후보를 그대로 평가하는 실행 코드를 준비하는 단계다.

근거 문서: [후보 Model Card](model_card.md), [보고서](report.md), [Top-20 개선 계획](EXPERIMENT_NOTES.md).

## 6. 사용자 실행 명령어

`src/sensor_ml/evaluation/evaluate_frozen_model.py`를 준비했다. 저장된 분류기·median·센서 목록·threshold를 그대로 사용한다. 현재 Profile은 기존 시간 검증 실행의 데이터 정의와 일치해야 하며 이를 저장 모델에 새로 적용하거나 학습하지 않는다.

```powershell
python -m src.sensor_ml.evaluation.evaluate_frozen_model --bundle-dir models/candidates/m3_sensor20 --train data/splits/integrated/time_train.csv --test data/splits/integrated/time_test.csv --reference-run logs/secom/v1/m3_policy80_40_time_validation/execution.json --output-dir logs/m3_frozen_time_evaluation --trusted-local-bundle --confirm-frozen-evaluation
```

- Test label·값을 읽고 평가하는 명령이다. 사용자가 평가를 실행할 때만 수행한다. 이번 코드 작성에서는 실행하지 않았다.
- split 역할·생성 계약·ID 비중복·시간 순서·입력 계약과 Train 출처를 확인한다. 센서 값·소스 바이트의 동일성이나 과거 모든 실행의 미사용을 보증하지 않는다.
- 모든 행을 평가하며 전체 선택 센서 결측 등 오류가 있으면 자동 제외하지 않는다. 입력 검증 실패는 실행 표식 생성 전에 중단한다.
- 평가 시작 시 묶음 폴더에 `evaluation_started.json`을 생성한다. 다른 출력 폴더로 같은 묶음을 재평가하는 것도 거부한다. 이는 묶음별 실행 관리이며 파일을 복사·삭제하는 행위까지 막는 보안 장치는 아니다.
- 표식 생성 후 오류가 발생하면 표식을 자동 삭제하지 않는다. 원인을 확인하기 전에 삭제·폴더 복사로 다시 실행하지 않는다.
- `test_result.csv`, `test_predictions.csv`, `evaluation.json`, `evaluation.md`를 저장한다. 목표 충족 여부는 기존 시간 검증 실행의 80%·40% 정책으로 계산하며 문턱을 재탐색하지 않는다.
- 관련 합성 테스트 17개 통과. 실제 Test 실행 결과는 아직 없다.

## 7. 사용자 실행 완료 기록

사용자가 동결 저장 모델을 실행했으며 `logs/secom/v1/m3_frozen_time_evaluation/evaluation.json`의 상태는 `completed`, `refit=false`다. 236행·불량 9건에서 TP 1·FP 30·FN 8·TN 197, Recall 11.11%·Precision 3.23%·F1 0.05·AP 0.040461·ROC-AUC 0.488008·양성 판정 비율 13.14%를 기록했다. 80%·40% 정책은 미충족이다.

과거 완전한 미사용 여부 보증 불가라는 평가 표현을 유지한다. 결과에 맞춰 모델·threshold·센서를 변경하지 않았으며 재실행도 하지 않았다. [보고서 34절](report.md#34-동결-저장-모델의-후속-시간-구간-평가-2026-10-07)·[Model Card](model_card.md)·README에 완료 상태를 반영했다. 1~6절의 실행 전 문구는 당시 기록이다.
