# WaferGuard 프로젝트 마무리 일정

작성일: 2026-10-09. 최종 기한: **2026-11-05**.

사용자가 정한 일정은 2026-10-12~2026-10-18 딥러닝 전처리, 2026-10-19~2026-10-25 에이전트 구현, 2026-10-26~2026-11-05 통합 테스트·보고서·발표자료 준비다. 기존 SECOM 머신러닝은 마무리 상태로 보존한다. 아래 체크박스는 예정 작업이며 구현·검증 완료를 뜻하지 않는다.

## 1. 기간별 목표

| 기간 | 주요 작업 | 담당 | 완료 기준 |
| --- | --- | --- | --- |
| 10/12~10/18 | WM-811K 딥러닝 전처리 | 양현승, 이종수 인수·검토 | 품질·분할·변환·캐시·Dataset 검증과 첫 배치 전달 |
| 10/19~10/25 | 제한적 자율 전처리 에이전트 | 양현승 | 전처리 연결·승인·중단/재개·최소 상태 기반 도구 선택, 보안 회귀 검증 |
| 10/26~11/05 | 통합 테스트·보고서·발표자료 | 공동, 담당 영역별 작성 | 재현 가능한 실행·평가·보안 검증 기록, 최종 보고서·발표자료·시연 준비 |

딥러닝 모델·학습·평가는 기존 담당인 이종수가 진행한다. 전처리 인수 후 에이전트 구현과 병행하며, 구체적인 모델 실험 일정과 동결일은 학습 환경·기준선 결과 확인 후 조율한다. 에이전트가 완성될 때까지 학습을 기다리지 않도록 전처리 코어는 단독 실행 가능하게 만든다.

## 2. 2026-10-12~2026-10-18: 딥러닝 전처리

기준 문서: [WM 전처리 상세 설계](WM811K/PREPROCESSING_DESIGN.md).

- [ ] 원본 출처·신뢰 여부·실제 구조·자원 요구량 확인.
- [ ] 원본 읽기·canonical 변환·라벨 정규화 구현.
- [ ] 맵 값·라벨·미라벨·Lot·중복·제외 사유 검사.
- [ ] 클래스·맵 크기·Lot 분포와 대표 패턴을 로컬에서 확인.
- [ ] Lot·중복 보호 분할과 비중첩·클래스 지원 검증.
- [ ] 2채널 입력·resize·마스크 보존·캐시·Dataset 구현 및 검증.
- [ ] 변환·클래스 매핑·분할 계약과 첫 배치를 이종수에게 전달하고 인수 확인.

10/18 완료 기준은 코드 작성만이 아니라 합성 입력 검증과 승인된 실제 입력의 처리 결과·전달 계약 확인이다. 원본 역직렬화의 신뢰·격리 조건이 충족되지 않으면 실행하지 않고 미충족 조건을 기록한다.

## 3. 2026-10-19~2026-10-25: 에이전트 구현

기준 문서: [기초 설계](agents/AGENT_BASIC_DESIGN.md), [상세 설계·OWASP 검증 기준](agents/AGENT_DETAILED_DESIGN.md).

- [ ] 전처리 도구 계약을 연결한 규칙 모드 구현.
- [ ] 원본·분할·변환 계획 승인과 정확한 작업에 결합한 승인 검증 구현.
- [ ] 로컬 기록·체크포인트·중단/재개·완료 결과 재사용 구현.
- [ ] 최소 상태 매핑·LLM 응답 검증·제한된 도구 선택 구현.
- [ ] 반복·재시도·요청·비용 한도와 실패 시 안전 경로 구현.
- [ ] 합성 fixture·mock provider 기반 보안 회귀 검사.
- [ ] OS 격리·네트워크·provider 정책 검증 결과와 미완료 항목 기록.

원본·상세 통계·식별 정보의 LLM 입력 금지는 유지한다. OS 격리·실제 egress 차단·provider 정책 등 활성화 조건이 검증되지 않으면 실데이터의 `bounded_llm` 모드는 차단한다. mock 검증 통과를 실데이터 보안 준수 완료로 표시하지 않는다.

## 4. 2026-10-26~2026-11-05: 테스트·보고서·발표자료

- [ ] 전처리 코어 단독 실행과 에이전트 실행의 필수 계약·결과 정합성 확인.
- [ ] 정상 완료·품질 실패·승인 대기·중단/재개·금지 요청 차단 통합 시연.
- [ ] 딥러닝 모델·전처리·평가 정책 동결 후 최종 평가와 저장·복원 검증.
- [ ] 보안 검증 SEC-01~16의 통과·실패·미검증·범위 제외를 근거와 함께 정리.
- [ ] SECOM·WM-811K의 독립 평가 결과, 한계, 설계 목적을 최종 보고서에 통합.
- [ ] 발표자료·시연 순서·재현 명령·환경 준비 사항 작성.
- [ ] 문서 링크·그림·용어·수치·오타와 공개 가능한 산출물 점검.
- [ ] 11/05까지 최종 제출본과 발표용 자료 준비.

두 데이터셋은 웨이퍼 단위로 연결되지 않으므로 통합 검출률이나 실제 2단계 성능을 주장하지 않는다. 평가 결과에 맞춰 Test를 반복 최적화하지 않는다. 발표자료는 딥러닝 결과가 정리된 뒤 확정한다.

## 5. 일정 운영 원칙

지금의 우선순위는 딥러닝 전처리 완성 → 학습 담당자 전달 → 에이전트 연결이다. 보안 단위 검증은 구현과 동시에 하고 마지막 기간에는 통합·환경 검증을 진행한다.

11/02부터 신규 기능 추가를 멈추고 오류 수정·보고서·발표 준비에 집중하는 것을 권장한다. 이는 사용자 확정 일정과 구분한 운영 제안이다. 지연 시 고급 모델·추가 LLM 기능·외부 추적 시연을 줄이고 데이터 계약·승인·원본 보호·필수 검증을 우선한다. 기한 때문에 보안 조건을 낮추거나 미검증 항목을 완료 처리하지 않는다.
